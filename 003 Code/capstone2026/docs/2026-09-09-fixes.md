# 설문·추천·방문 기록 수정 내역

## 변경 사항

- `SurveyActivity`는 `users/{uid}`의 `user_tags`, `priority_tag` 저장이 성공한 뒤 추천 화면으로 이동합니다. 저장 실패 시 같은 화면에서 재시도할 수 있습니다.
- `SurveyPreferences`는 새 설문 형식을 우선 읽고, 새 필드가 없는 기존 계정은 `bean_tag`, `style_tag` 등 이전 형식으로 읽습니다. 중복·알 수 없는 태그는 제거합니다.
- `RecommendationLoader`를 홈과 추천 목록에서 함께 사용합니다. 화면 진입 시 계정 설문, 카페 목록, 위치를 읽어 우선순위를 포함한 추천을 다시 계산합니다. 추천 목록의 전역 static 의존성을 제거했습니다.
- 위치 권한이 없거나 위치 조회가 실패·시간 초과되면 대전 궁동·어은동 좌표를 사용하고 화면에 기준 위치를 표시합니다. 카페 좌표가 없으면 거리 보너스를 주지 않습니다.
- 추천 화면의 검색 조건과 선택한 정렬 방식은 평점·개인화 데이터가 늦게 도착해도 유지됩니다. 화면 복귀 시 즐겨찾기와 과거 별점도 다시 반영합니다.
- 즐겨찾기와 최근 본 카페는 로그인 UID별 SharedPreferences에 저장합니다. 최근 본 카페에는 카페 ID도 저장합니다.
- 새 방문 기록은 `cafeId`와 `cafeName`을 함께 저장합니다. 상세 리뷰, 추천 목록의 평점·개인화, 홈 인기 카페를 ID 기준으로 연결합니다. 배지 계산도 해당 ID의 카페를 조회합니다.
- 방문 기록 수정은 기존 문서의 작성자를 확인하고 평점과 메모만 갱신합니다. 카페 ID·작성자·방문 시각을 덮어쓰지 않습니다. 저장 중 중복 클릭을 막습니다.
- 상세 화면의 가짜 기본 전화번호를 없앴습니다. 실제 번호가 없으면 전화 버튼을 비활성화합니다.
- 네이버 인증 값이 비어 있으면 API 호출을 생략합니다. 검색어를 URL 쿼리로 인코딩하고 응답 리소스를 닫습니다.
- 시작 화면의 존재하지 않는 버튼 참조를 제거하고 화면 종료 시 지연 이동을 취소합니다.
- Firebase Auth의 별도 버전 지정과 중복 선언을 제거하여 기존 Firebase BOM이 버전을 관리하도록 통일했습니다.

## 기존 데이터 처리

- Firestore의 기존 데이터에 일괄 쓰기·삭제·마이그레이션을 실행하지 않았습니다.
- ID 없이 이름만 있는 방문 기록은 카페 목록에서 그 이름이 유일할 때만 해당 카페 평점에 포함합니다. 같은 이름의 매장이 여러 개면 임의 연결하지 않습니다. 해당 기록 자체는 개인 방문 이력과 커뮤니티에 남습니다.
- 기존 기기 공용 즐겨찾기/최근 본 카페 파일은 삭제하지 않았습니다. 소유 계정을 알 수 없어 새 계정별 저장소로 자동 복사하지 않으며, 새 목록에서는 보이지 않습니다. 계정별 즐겨찾기는 다시 등록해야 합니다.
- `MainActivity01`, `SurveyActivity01`, 미사용 Room DAO 등 별도 구현은 제거하지 않았습니다.
- 네이버 인증 값은 여전히 비어 있으므로 실제 리뷰 분석을 활성화하려면 별도 설정이 필요합니다.

## 실행한 검증

Android Studio의 번들 JDK를 사용해 다음을 실행했습니다.

```powershell
$env:JAVA_HOME = 'C:\Program Files\Android\Android Studio\jbr'
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:lintDebug --console=plain
```

- 결과: `BUILD SUCCESSFUL`
- 단위 테스트: 16개 성공(추가 회귀 테스트 15개 + 기존 예제 1개), 실패 0개
- Lint: 오류 0개, 경고 318개. 문자열 하드코딩, 번역·형식화, 의존성 업데이트 등의 경고는 남아 있습니다.
- APK: `app/build/outputs/apk/debug/app-debug.apk`
- 실제 기기/에뮬레이터 및 실제 Firebase 계정으로 아래 시나리오를 실행하지는 않았습니다.

## 기기에서 확인할 시나리오

1. 설문을 완료하고 추천 화면을 확인한 뒤, 취향과 우선순위를 바꾸어 다시 설문을 제출합니다. 새 조건에 따라 점수가 바뀌는지 확인합니다.
2. 추천 목록에서 평점순·거리순을 선택하고 상세 화면에 다녀옵니다. 선택한 정렬 및 검색 조건이 유지되는지 확인합니다.
3. 계정 A에서 즐겨찾기를 등록하고 계정 B로 로그인합니다. A의 즐겨찾기가 B에게 표시되지 않고, A로 돌아오면 다시 보이는지 확인합니다.
4. 같은 이름의 서로 다른 두 매장에서 각각 방문 기록을 작성합니다. 각 상세 화면과 평점이 섞이지 않는지 확인합니다.
5. 기존 방문 기록의 메모를 수정하고 카페·작성자·방문 시각이 유지되는지 확인합니다.
6. 추천 화면을 열고 Android가 프로세스를 종료한 후 화면을 복원합니다. 목록이 다시 로드되는지 확인합니다.
7. 위치 권한을 거절하거나 위치를 끕니다. 기본 지역 안내와 함께 추천이 표시되는지 확인합니다.
8. 네트워크를 끊은 상태에서 설문 저장 및 추천 재시도를 확인합니다. Firestore 캐시가 있으면 기존 데이터가 표시될 수 있으며, 새 설문 저장은 서버 응답을 기다립니다.
