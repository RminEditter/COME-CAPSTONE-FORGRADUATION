# 프로필 마이페이지 구현 및 검증 (2026-09-09)

## 구현 완료

- 기존 activity_profile.xml을 마이페이지로 교체하고 ProfileActivity에 연결했습니다. 중간 초안 activity_profile_dashboard.xml은 통합했습니다.
- 닉네임과 기본 컵 아바타, 프로필 편집, 카페 취향 칩과 우선순위, 설문 다시 설정, 기록·즐겨찾기·배지 바로가기, 로그아웃을 제공합니다.
- 현재 계정 users/{uid}에서 프로필을 읽고, visit_records의 userUid로 방문 기록 수를 계산합니다. 방문한 고유 카페 수가 아니라 작성한 기록 수입니다.
- 즐겨찾기는 AccountPreferences의 계정별 로컬 저장값 중 true 개수입니다. 다른 기기와 동기화되는 서버 통계는 아닙니다.
- 획득 배지는 users/{uid}/badges 중 unlocked=true인 문서 개수입니다.
- 화면 복귀 시 다시 조회합니다. 이전 계정 또는 종료된 화면에 도착한 응답은 무시하고, 재조회할 때 이전 표시값을 초기화합니다.
- 로딩·빈 데이터·조회 실패를 구분합니다. 실패한 통계는 0으로 표시하지 않으며 다시 불러오기 버튼을 제공합니다.
- ProfileEditActivity를 별도로 추가했습니다. 닉네임(1~20자), 성별, 나이대만 merge 저장해 설문 필드를 보존합니다. 최초 조회 실패 시 편집을 막고 재시도를 제공합니다.
- 편집 초안을 화면 재생성 시 복원하고, ViewModel에 진행 중인 저장을 보관해 회전 중 중복 저장 요청을 막습니다.
- 시스템 바/키보드 여백, 접근성 제목·통계 설명, 큰 글꼴의 세로 통계 및 가변 높이 하단 메뉴를 적용했습니다.

## 검증 결과

- Debug APK 빌드 성공.
- 기존 단위 테스트 16개 통과 (CafeIdentity 4, Recommender 7, SurveyPreferences 4, 기본 1).
- Android 15 / API 35 에뮬레이터에서 계측 테스트 6개 통과 (프로필 5, 기본 1).
- 프로필 테스트는 실제 XML과 ProfileDashboardView에 예시 데이터를 연결합니다. 정상 통계·취향, 빈 데이터와 오류 구분, 재조회 초기화, 320dp/360dp와 글꼴 1.6배, 야간 설정 및 편집 화면의 가로·세로 텍스트 잘림을 확인했습니다.
- 생성된 8개 화면 이미지를 확인했습니다. 이미지 저장 위치는 app/build/profile-previews/이며 빌드 산출물이므로 Git에 포함하지 않습니다.
- Lint: 오류 0개, 경고 308개. 전체 프로젝트의 경고가 모두 해소된 상태는 아닙니다.
- Git 커밋/푸시는 수행하지 않았습니다. 신규 Java/XML/테스트 파일도 함께 포함해야 합니다.

## 아직 직접 확인하지 않은 사항

위 화면 테스트는 실제 로그인이나 Firebase 데이터 변경 없이 실행했습니다. 실제 계정 환경에서는 아래 흐름을 최종 확인해야 합니다.

1. 프로필 편집 후 복귀하여 닉네임이 갱신되고 기존 설문 응답이 유지되는지 확인.
2. 설문·방문 기록·즐겨찾기·배지 화면에서 변경 후 돌아와 표시값이 갱신되는지 확인.
3. 서로 다른 계정으로 로그인해 정보가 섞이지 않는지 확인.
4. 네트워크 단절/Firestore 권한 오류 후 재시도, 저장 중 화면 회전 및 키보드 표시 상태 확인.

최근 활동 피드, 프로필 사진 업로드, 대표 배지·진행률, 커뮤니티 내 게시글 메뉴는 이번 범위에 포함하지 않았습니다.
